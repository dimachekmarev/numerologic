Полный пошаговый план для запуска приёма оплаты. От выбора провайдера до первой живой транзакции.

## 1. Юридическая подготовка (1–2 недели)

### 1.1 Регистрация
- [ ] **ИП или ООО** — для приёма платежей нужно юрлицо
  - ИП проще: регистрация за 3 дня, госпошлина 800₽
  - Для самозанятых: подходит только для услуг физлицам, не для digital-продуктов с автоматической выдачей
  - ОКВЭД: 62.01 (разработка ПО), 63.11 (деятельность по обработке данных)
- [ ] **Расчётный счёт** — в любом банке с интернет-эквайрингом (Тинькофф, Точка, Альфа)
- [ ] **Регистрация в ФНС** — если ещё не стоит на учёте

### 1.2 Документы
- [ ] **Оферта** — публичная оферта на сайте (страница `/terms`)
  - Предмет: digital-продукт (разбор, практикум, доступ)
  - Момент оказания: мгновенно после оплаты
  - Условия возврата: 14 дней для невозвратных digital-товаров с согласием
  - Реквизиты продавца
- [ ] **Политика конфиденциальности** — страница `/privacy`
  - Соответствие 152-ФЗ (персональные данные)
  - Указание оператора данных
  - Цели обработки, сроки хранения
- [ ] **Согласие на обработку данных** — чекбокс при оформлении заказа (уже есть)
- [ ] **Согласие на начало оказания до истечения срока возврата** — для digital-продуктов

### 1.3 Налогообложение
- [ ] **Выбор системы** — УСН 6% (доходы) или УСН 15% (доходы минус расходы)
  - Для digital-продуктов обычно выгоднее УСН 6%
  - Налог платится с полной суммы до вычета комиссии эквайринга
- [ ] **Онлайн-касса** — 54-ФЗ требует отправку чека
  - Облачная касса: Атол Онлайн, CloudKassir,OrangeData (~3 000–5 000 ₽/мес)
  - Или через эквайринг-провайдера (ЮKassa, Тинькофф включают кассу)
- [ ] **Фискальный накопитель** — если своя касса (~10 000 ₽ на 15 месяцев)

## 3. Техническая интеграция (2–5 дней)

### 3.1 Серверная часть

#### Переменные окружения
```bash
# Платёжный провайдер
PAYMENT_PROVIDER=yookassa         # yookassa | tinkoff | cloudpayments
PAYMENT_SHOP_ID=xxxxx             # ID магазина
PAYMENT_SECRET=xxxxx              # Секретный ключ
PAYMENT_WEBHOOK_SECRET=xxxxx      # Для верификации webhook

# URL
PAYMENT_RETURN_URL=https://numerologic.app/checkout/success
PAYMENT_CANCEL_URL=https://numerologic.app/checkout/cancel
PAYMENT_WEBHOOK_URL=https://numerologic.app/api/webhook/payment

# Режим
PREVIEW_MODE=false                # false = реальная оплата
```

#### Webhook endpoint
```javascript
// POST /api/webhook/payment
// Принимает уведомления от провайдера
// Верифицирует подпись
// Обновляет статус заказа
// Генерирует материал при успешной оплате
```

### 3.2 Процесс оплаты (flow)

```
1. Пользователь нажимает "Перейти к оплате"
2. Frontend → POST /api/checkout → создаёт заказ в БД
3. Backend → API провайдера → создаёт платёжную сессию
4. Backend возвращает { checkout_url, order_id }
5. Frontend перенаправляет на checkout_url
6. Пользователь платит на странице провайдера
7. Провайдер → webhook → POST /api/webhook/payment
8. Backend обновляет заказ: status=paid
9. Backend генерирует материал/открывает доступ
10. Провайдер перенаправляет на /checkout/success?order_id=xxx
11. Frontend загружает подтверждение из API
```

### 3.3 База данных — таблица заказов

```sql
CREATE TABLE orders (
  id INTEGER PRIMARY KEY,
  owner INTEGER NOT NULL REFERENCES accounts(id),
  product_slug TEXT NOT NULL,
  amount INTEGER NOT NULL,         -- в копейках
  currency TEXT DEFAULT 'RUB',
  status TEXT DEFAULT 'pending',    -- pending | paid | refunded | cancelled
  provider TEXT,                    -- yookassa | tinkoff
  provider_payment_id TEXT,        -- ID платежа у провайдера
  created_at INTEGER NOT NULL,
  paid_at INTEGER,
  refunded_at INTEGER
);
```

### 3.4 Тестовый режим

В режиме `PREVIEW_MODE=true`:
- Создаются тестовые платежи (без списания денег)
- Webhook принимает тестовые уведомления
- Можно проверить весь flow

В режиме `PREVIEW_MODE=false`:
- Реальные платежи
- Тестовые платежи запрещены (уже реализовано)

### 4.2 Переменные окружения
```bash
AI_API_KEY=sk-xxxxxxxxxxxxxxxx
AI_BASE_URL=https://api.openai.com/v1     # или https://api.anthropic.com
AI_MODEL=gpt-4o-mini                       # или claude-3-5-haiku-20241022
```

### 4.3 Расчёт стоимости
- 10 запросов/день × 30 дней = 300 запросов/месяц на пользователя
- ~2000 токенов на запрос (контекст + ответ)
- GPT-4o-mini: ~$0.0003/запрос × 300 = $0.09/пользователь/месяц
- При 100 пользователях клуба: ~$9/месяц на AI

### 4.4 Лимиты и защита
- ✅ 10 сообщений/день (уже реализовано)
